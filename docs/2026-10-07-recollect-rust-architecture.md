## 1. 三库（T2、T8）

三个 SQLite 文件，永不共库、不许 `ATTACH`、不许跨库 SQL（继承计划 GC①）。同机一致性用"顺序写 + 崩溃窗口可判定"处理，不用分布式事务。

| 库 | 内容 | 谁能写 | 可否整层重建 | 是否下行到节点 | 是否进每日备份 |
|---|---|---|---|---|---|
| **会话库** `transcript.db` | 事实：`sessions` / `turns`（含来源 agent、机器、会话键、每条正文与生成时间、会话级最后保存时间、归属、`turn_key_tier`） | `P`（摄入路径），append-only——**唯一例外是运维面 `purge`，它是"按来源撤销"而不是"改写"**（D3） | 它是**源**，不重建；坏了只能靠备份恢复 | **否**（只上行） | **是**，7 份 |
| **记忆库** `memory.db` | 三族：**事实族**（实体/别名/事件/断言/卡片/出处）、**推导族**（关系边/因果卡/软边）、**判定族**（表态 `attestation`、抑制账 `retirement`、行上冷却列）；外加可删重建的索引 | 唯一写者（中心进程内锁）。前两族的内容列由 `X` 写；判定族里 `attestation` 由 `A`/`C` 写、`retirement` 由 `C` 写、冷却列是 `P` 独占的时间列（守卫 11 的列归属在这一族里照样成立） | **分两型，见下**（G4 的判据在此） | **是**，整份替换 | 前两族**否**；**判定族是**（单独导出，见 D9） |
| **水位库** `ledger.db` | 账：导入日志、蒸馏游标与蒸馏记录、推导游标与扫描轮次计数器、**反馈的落地（被引用 / 被否；不含任何匹配度分数）**、维护操作记录、心跳读数、**三个用量计数器（§9.5：LLM 烧灼度 / 按设备 ingest / agent 面工具调用）** | 唯一写者 | **否**——它记录重建的历史，自己不可重算 | **否**，永不出中心 | 否（丢了从会话库全量重蒸；**用量计数丢了就是丢了，它不参与任何判定**） |

**"重建"有两个形状，混成一个就会破约**（本轮读出的一处真实矛盾：原表述"记忆库是派生物、重算即可"对**判定族不成立**）：

- **派生重建**：删光**事实族 + 推导族 + 索引**，重蒸事实、重跑推导。**判定族一行都不许碰**——抑制账与表态记录的是"谁在什么时候基于什么否掉了它"，这些信息**不在转录层里**，重算不出来。若重建顺手清了它，症状正是守卫 13 要防的那件事：**已退场的记忆复活，且没有任何一处会报错**。
- **整库重置**（= `restore` 的路径）：连判定族一起回到备份里的某一刻。D3 那句"重置与重建是同一段代码"只在派生重建这一型成立；重置必须把判定族一并换掉。
- G4 的验收项"删光记忆层后重建，库回到可检索状态"按**派生重建**测——可检索性本来就不依赖判定族，两条不冲突。

**分库的刀口是一条可执行的判据**：*节点侧有读者的状态进记忆库（因为记忆库是唯一会下行的库）；只有中心有读者的账进水位库。* 于是——

- `retirement`（抑制账）与 `cooldown_until` 住**记忆库**：前者被守卫 13 要求"必须随快照下行"，后者被 `probe` 在节点上逐行读。它们是**状态**不是日志。
- 蒸馏游标、"这个会话蒸过几轮、产出多少行、拒收几行"住**水位库**：节点上没有读者，且它是历史而不是当前态。
- 转录行上**不许有任何派生列**（"是否已提取"整个搬到水位库），这是本轮对 Python 侧 §3.2 把 `distill_state` 放记忆层、而 §3.2.1 又归 `P` 那处三向不一致的收口。

**一条必须写死的推论**：水位库不可重建、不下行、不备份 ⇒ 它坏掉的后果是"中心不知道自己蒸到哪"，处置 = 从会话库全量重蒸（`restore` 那条路径），**不许**因为水位丢了就把记忆库当权威去改。

**索引**住记忆库文件内，但影子表名与 token 形状对 `index` 模块之外全私有（守卫 2 的形态）。向量一期不做（继承账本 §3.5）。

## 2. 职权分离（T1、T2、T8）

四个 actor，沿用 `P / X / C / A`（`H` 在 Python 侧第八轮整行删除，Rust 侧不再发明第五个）。

- `P` 程序：身份、时间、哈希、归属、水位、版本六类列独占。内容列对它不可见。
- `X` LLM 抽取：**内容列的唯一写入者，且必带 `provenance`**，缺出处即写入失败（§3.2.1 规则 2 原话，无例外）。只在后台作业里活着。
- `C` 中心自己：判定与状态机——`verdict`、`superseded_by`、`resolved_at`、`attested` 的落笔人。
- `A` agent：只经表态入口，正面表态四型必带解析到人工轮的锚，`rejected` 与退场免锚。

**Rust 侧的关键改动**：actor 不再是运行时字符串或"谁调的"这种口头约定，而是**四种不同的入参类型**，各自只暴露自己能写的列。`assert_writable(列, actor)` 这种运行期校验降级成"写不出这个函数"。声明式列归属表仍然保留，但它的职责收窄成两件事：① 生成 `X` / `A` / `C` 那三种写入类型的字段集，外加第四个 `WriterP`——它只有一个字段 `cooldown_until_ms`，因为冷却是**唯一一个在读路径上被写的 P 列**（§1 的冷却列 + D4 的窗口）；其余 P 列仍由摄入路径自己拿，不走这张表；② 与库内实际列做**双向覆盖率对拍**（未登记列默认拒绝）。守卫 11 的五条子检查里，①②③由类型承担，④⑤仍是真机用例——因为不对称锚定和"解除只有一种落库形状"是数据问题，不是构造问题。

**人的口子**：只有运维面六条命令（`pair` / `revoke` / `sync` / `doctor` / `purge` / `restore`），零记忆正文、零路径。`purge` 与 `restore` 与唯一写者同侧这条继承原论证：毁数据与换库的能力不许长在节点侧。

## 2.5 授权层：六种权限各自的单位与守门点（本轮新增；§2 管归属，本节管资格）

你问的是五种，这里拆成六行是因为**"删除"其实是两个动作**：让它对 agent 消失（降权，可撤销）与让它从磁盘消失（物理删除，不可逆）。把它们写成一行，实现时就会只剩下不可逆的那一个。

**先把两件事切开**，因为它们一直被混用：§2 的 actor 归属回答"**谁能写这一列**"，是**类型层**的事；本节回答"**谁被允许触发这条路径**"，是**入口层**的事。混用的后果很具体——归属正确但资格没人判，就会出现"每一列都写对了，但不该写的那台机器写了"。

**一条总则：资格只在入口判一次，判完以类型传递，业务 crate 内不再判第二次。** 理由是失败形状：两处判定就可能依据不同（一处看 token、一处看配置），而它们不一致时的症状是"某些请求通、某些不通且没人说得清"。落到 Rust 上就是入口装配出一个 **capability 类型**（每个权限一个零大小类型），业务函数签名要求它——**"没被授权"这个形状在业务层不存在，正如守卫 5 那同一个技巧**。

| 权限 | 单位（谁能拿到） | 执法点 | 拒绝时的返回 |
|---|---|---|---|
| **读** | **已配对设备**。不是用户、不是项目、不是会话 | `mcp` 组合根（本机 IPC）/ `query`+`snapshot` 端点（验签） | `unavailable`（未配对 / 公钥不符） |
| **写（转录层）** | **已配对设备，且只能写自己 `device_id` 署名的记录** | `ingest` 入口验签 + **署名必须等于配对时的 device_id**，不自选 | `authorization`（署名与凭据不符，逐条拒收） |
| **维护（判同 / 审核 / 推导 / 重建 / 备份）** | **仅 `hub` 本机进程**。任何远程端点不许触发 | `hub` 组合根；远程侧**没有一条路径能到达** cycle 入口 | `authorization`，并明写"维护只能本机触发"这一句原因 |
| **降权 / 退场** | `A`（agent 表态，需锚）与 `C`（审核判定） | 表态入口。**agent 面永远构造不出"删除"这个动作**——这是守卫 12 之外的第二条不可见性 | 免锚只限 `rejected` 与退场两型（继承原规则） |
| **删除（物理）** | **运维面 `purge`，仅本机、需人显式授权** | `hub` 组合根 + 见下面"删除的两阶段" | 拒绝一切远程调用 |
| **同步覆盖（下行整替）** | **验签通过 + `(epoch, seq)` 单调 + schema 版本在区间内**，三者缺一即拒 | `node` 侧收快照的入口 | `unavailable` / `validation`，且**绝不静默保留旧副本而不报警** |

**四个决定，附它们各自防的那件事**：

1. **读权限按设备，不按项目。** 任何库内 ACL 都会造出"两个 agent 看到的是两套真相"，直接撞 G1。查询噪声用 `scope` **过滤参数**解决（它是查询条件，不是保密边界），保密压在 mesh 与配对上。**这条要显式记住它的代价：同一台机器上的其它进程能读这三个 SQLite 文件（一期不加密）**——一期接受，因为加密密钥在 Pi 上只能落文件，那等于换个名字。写在这里而不是藏在实现注释里。
2. **远程不许触发维护作业。** 否则一个节点能让中心跑 LLM、烧光配额，而这正是 P5 那条读数要防的"配额耗尽 ⇒ 静默停止产出"的一个攻击面。运维要远程触发只能走 `sync`/`status` 这类零配额读数。
3. **删除是两阶段：先降权，再删。** `purge` 的默认动作是**写抑制账**（对 agent 立刻不可见，可撤销），带 `--confirm` 才真删转录行与派生行。理由：唯一不可逆的动作应该有一个人给的授权，而且"先让它沉默、再让它消失"这两步之间任何一步出问题都不会丢数据。这也让 D3 那句"按来源撤销"有了自然的中间态。
4. **覆盖必须比"验签通过"更强——这是本轮找出的一个真实漏洞。** 原设计里节点只看 `sha` 与 `seq`，而 **`restore` 恰恰会把中心的 `seq` 打回旧值**（从 7 天前的备份恢复），于是每个节点都会正确地拒绝这份"倒退"的快照，症状是**恢复完成后全网的记忆停在恢复前那一刻，而中心的日志显示一切正常**：备份生效了，节点不知道。修法是引入 **`snapshot_epoch`**：每次 `restore` 让 epoch 单调 +1 并重置 seq，节点判 `(epoch, seq)` 二元组单调。**epoch 的初值是随机数，不是 0**，这样"换了个全新中心"也不会被旧节点误接受。这条改的是承诺面之外的内部协议（明令可自由重定），所以不需要走 C2 谈判。

## 2.6 返回形状与守门点（"谁守门决定"的回答）

**三种出口，一个构造者**：

| 出口 | 形状 | 消费方 | 守门的类型 |
|---|---|---|---|
| 工具返回 | JSON，带 `schema_version` | 宿主 agent | `rc-agent` 里的返回构造器（**系统内唯一能携带正文的类型**，守卫 12） |
| 注入块 | stdout 纯文本，**围栏 = 每行前缀 `[recollect] `**；硬上限 3 行 = stdout 的**物理行数**；**沉默即空输出 ⇔ `stdout.is_empty()` ⇔ 零字节** | 宿主解析 | 同上，且 `hook` 是唯一产出者 |
| 导出件 | Markdown，含被拦项与原因、"还有 N 行未列出" | 人，经 agent | `rc-agent` 的 export 构造器 |

**为什么"一个构造者"比"一个校验器"可靠**：校验器是运行期的，能被忘记调用；构造器是唯一能把字段装成返回类型的入口，**忘记调用它 = 写不出这个函数**。守卫 12 已经用同一个技巧管住了正文，本节只是把它扩到"形状"。

**返回必须分四类错误，不许合并成"失败"**：`authorization`（你不该做这件事）/ `validation`（你给的输入不对，逐条给原因）/ `unavailable`（现在不能用，重试可能有用）/ `empty`（库就是没有）。判据是消费者动作：**这四类我作为 agent 的下一步行为完全不同**——放弃并告知 / 改输入重试 / 静默重试 / 继续干活。合并成一条"error"就等于逼我猜，而猜错的方向总是最贵的那个（把"未配对"读成"库里没有"，我会停止使用这套系统；这正是 G7 那条失效形状的另一半）。

**能力协商**：`status` 返回 `capabilities`（本版本支持哪些可选字段与工具位）。有了它 + "只增不减 + 忽略未知字段"那条 C2 演进规则，老宿主连新中心不需要同步升级——**这是唯一能防住"中心先升级把宿主打挂"的办法**，而单机期一结束就一定会发生。

| 10 | 代词不许成为实体别名 | **运行期（唯一写入口）** | 闸门在每个人工轮开闸这个后果，类型系统看不见 |

| 12 | 记忆正文只许从 agent 面出口 | **类型 + 真机用例** | 承载正文的类型与承载"计数/状态/id"的类型分开；金丝雀全库扫那条用例原样继承 |
| 13 | 退场不许复活 | **真机用例（双段）** | 写侧查账这件事只在跑起来才看得见。账按内容不按键 + 诚实夹具 + 副本旁路探针三条一起继承 |
| **14** | **资格只在入口判一次，业务层不得再判**（Rust 轮新增） | **编译期** | 每个权限一个 capability 零大小类型，由组合根装配；业务函数签名要求它——"未被授权"这个形状在业务层不存在。同 §2.5 总则 |

**一条自检**：十四条按承担层数一遍——**编译期 8 条**（1、2、4、5、7、11、12、14，其中 1/11/12 是"编译期 + 真机用例"双担），**依赖图 2 条**（3、6），**运行期 1 条**（10），**真机用例 2 条**（8、13），**作废 1 条**（9）。凡填"编译期"的，实施计划里必须写一条**故意越界的编译失败测试**——"一条从未红过的守卫等于没有守卫"这条纪律在编译期同样成立，否则"编译不过"只是我的断言而不是证据。

## 4. crate 拓扑（三个切法与定案）

**切法一 · 按业务模块切（15 个 crate）** —— Python 侧职责表一比一搬。编译执法最多，但一期不做的东西（向量、builder 角色）会让几个 crate 在第一期没有住户。空 crate = 没有读者的功能，直接违反 GOALS §4 末那条理由。**否**。（本轮范围改判把同步与抽取拉进一期后，这个切法被否的理由少一半，但剩下的那一半仍然成立，且它解决的正是切法三要解决的问题——见下。）

**切法二 · 按语言习惯切（1 个 lib + 5 个 bin）** —— 最省事，但守卫 1/2/4/6/12 全部退回"运行期扫描"，等于换语言没买到任何东西。**否**。

**切法三 · 按句柄能力切（定案）** —— crate 边界画在"谁被允许命名哪种句柄"上，而不是画在业务名词上。理由：这十四条守卫里有一半的失效形状都是"某个模块拿到了它本不该拿到的能力"，而在 Rust 里唯一不需要新增测试就能拦住这种东西的机制，就是**那个类型在它的作用域里不存在**。

```
rc-contract   入库契约与校验、逐条拒收原因、随仓库外发的 schema（零内部依赖，可独立发布）
rc-store      三库句柄类型、DDL、迁移梯子、落地路径（新名+指针+sha256）、能力自检
              └ 唯一能构造"双柄"的那个 struct 住这里的私有导出面
rc-ledger     会话库读写 + 水位库读写        → 只认 transcript / ledger 两种句柄
rc-memory     记忆库全部表 + 声明式归属表 + 四种写入者类型（X 内容列 / A 表态 / C 判定与状态机 / P 冷却列）  → 只认 memory 句柄
rc-index      FTS5 + CJK 影子 + 版本标记；可整层重建   → 记忆句柄由 rebuild 的必填形参注入（原文写"会话句柄"是笔误：`rc-index` 若收会话句柄就成第二个双柄持有者，破守卫 1）
rc-search     一份实现两个数据源（live / replica）；排序与闸门分离
rc-agent      MCP 五工具 + 注入契约 + 三态闸门 + 围栏产出（全系统唯一能输出正文的 crate）
rc-llm        后端接口 + 探针 + 家族墙钟预算 + 失败矩阵
rc-distill    抽取 / 判同 / 审核三作业 + 配额 + 心跳 + 蒸馏与推导水位推进
              └ 全系统唯一被允许命名"双柄"的 crate
rc-derive     推导作业（关系 / 因果 / 时间线）+ 异常扫描 + 定期 LLM 复核
              └ 只认 memory 句柄：它在类型上拿不到会话库，"推导不许绕过记忆层直接读原文"因此不是守卫而是编译期事实
rc-net        协议定义一份 + 中心侧 + 节点侧两个实现（不共享实现）
rc-diag       能力与平台自检 + doctor 视图（零正文、只计数）  → 本 crate 自阶段 2 起交付；阶段 1 的自检住在 rc-store::capability + doctor bin，不在这里

bin targets： hub   node   mcp   hook   doctor     （五个，各自是一份独立的依赖声明）
```

**第一期住户**：全部非空。`rc-net` 两侧实现都住一期——**因为本轮范围改判把同步与设备身份拉进了一期**（GOALS §4、§5.4），G1 的"两台机器同一份数据"与 G5 的"拷进空机器两条路都能跑"都要节点侧真跑一次才成立；押后的是向量与 builder 角色，不是网络侧。**唯一押后的形状**是端点集合里的 `vectors` 与 `snapshot/vectors`（类型住一期交付，实现不做）。**这是"预留位置"与"空 crate"的区别**：定的是类型与承诺，不是壳。

**`hook` 的依赖集是这份架构最硬的一条边界**：`{rc-store, rc-search, rc-index, rc-memory, rc-agent}`，其中 llm、ledger、net 三个**不在**里面。两处与原表的差异各有理由：**少 `rc-contract`**（V1）——`hook` 不解析 `ExchangeFormat`、不做内容寻址，而词面归一只有一个家（`rc-index::analyzer::norm_token`），挂上契约等于给"归一有两个家"留门；**少 `rc-diag`**（V11）——能力自检在阶段 0 已落地为 `rc-store::capability::probe` + `doctor`，而 `hook` 里没有任何一条命令渲染诊断视图，**`rc-diag` 自阶段 2 起进入这个依赖集**（那时 doctor 视图开始读记忆库侧计数）。多出来的一项同样是 V1：probe 每次注入都要写冷却列，写它必须经 `rc-memory` 的写入者类型（守卫 11 的列归属在类型层）。

## 5. 入库格式（T2、T5）

`ExchangeFormat` 是 C1 承诺面，也是唯一"别人写的代码喂进来的入口"。

- 三档 turn 身份（自带唯一 id / 可承诺稳定序号 / 只有内容可辨），**缺省落最低档，禁猜高档位**；档位声明必须可证伪——"声明高档但 id 重复或为空"的批次整批拒收并逐条给原因。T1 的证伪判据是**标识性而不是单调性**：同一会话内同一序号被不同 role 声明 ⇒ 它标识的是"某类 turn 的第 N 条"而不是 turn，声明为假（`seq_not_stable`）；同序号同 role 不同正文是合法的**重生成/分支**，两行都保留，不许拒。没有这条判据时 T1 唯一可查的是"序号填没填"，于是给每条都填 0 的弱源能永久伪装成 T1。
- 身份字段逐字节照抄不清洗；正文归一（CRLF→LF + NFC + strip，内部空格保留）。
- 跨 target 逐字节对拍是**验收项**：同一份导出在 `arm64 Linux` 与 `x86_64 Windows` 上算出的 turn 身份与正文指纹必须完全相同。`turn_uid` 的黄金值文件是本期唯一跨语言可原样搬的资产（JSON + 每档写死全 hex + 人眼对一遍 + 第二台机器重算）。
- 一期就发**机器可读 schema + conformance kit**，且 kit 不接触中心即可跑通。
- **输入侧只有一种格式，输出侧有两种**（这条补齐 Python 侧"出向格式"那处未定）：给 agent 的返回是 C2 的 JSON 形状，给人的是 C3 的 Markdown 导出件（含被拦掉的行与原因、超上限明写"还有 N 行未列出"、不许静默截断）。导出件由调用方落盘，我们不替人决定文件放哪。`这个前缀同时是阶段 2 抽取侧 _prepare 的剪除标记——围栏与剪除标记必须是同一个字符串，否则注入过的内容会被当成人类的输入蒸回库里。`

## 6. 接口与入口（T4）

**五个入口 = 一个可执行文件的五个 build target**，按角色启用；单机时中心与节点同进程，加第二台时才决定谁是中心，规则仍是"已有转录数据那台当中心"，选错不用搬迁（会话库可重导入）。

**面向宿主的三种形态，职责互不重叠**：

| 形态 | 谁拉起 | 生命周期 | 干什么 |
|---|---|---|---|
| **MCP server**（`mcp`） | 宿主 | 长驻，每会话一个 | 五工具：`recall` / `remember` / `vote` / `status` / `export`。**`probe` 不在这张清单里**（V12：它的产物是带围栏的 stdout，消费者是 `hook`；做成工具等于给同一个形状造两个入口，3 行上限的执行点也变成两处）。"在线走中心"本阶段成立；**"离线读本地副本并响亮标 `source: replica`" 归阶段 4**——副本落地文件是下行整替的产物，阶段 1 没有它。阶段 1 的 `mcp` 因此**没有 `--replica` 入口**，而 `status`/`export` 的 `source` 字段形状已经预留（值恒为 `live`），加它是加法不是改约。 |
| **hook**（`hook brief` / `hook probe`） | 宿主的 `SessionStart` / `UserPromptSubmit` | 短命，同步 | 只输出一段 stdout：`brief` 是 L1 状态块，`probe` 是三态闸门结果，**沉默即空输出** |
| **skill / L0 指令片段** | 宿主加载，不是进程 | 静态文本 | 教 agent 什么时候该查、怎么查（含处境路由那一行：用户在谈自己的状态 ⇒ 先 `recall(kind∈{assertion,event})`）。**它不是插件系统**，是一份随仓库发布的说明文本 + 一个内嵌常量，产物里两者同源（一条对拍守卫） |

**离线写路径的定案（2026-10-21 改实，原句附后）**：中心不可达时 `vote` / `confirm` / `resolve` 一律响亮拒绝并给出可诊断原因，**绝不在本地排队等上行**——**记忆库副本只读**，任何本地记忆写在下次整替时被静默吃掉。
**改实的那半句是 `remember`**：在**节点**上它走正常路径写**本机转录层**（阶段 4 的 `NodeRoot` = transcript RW + ledger RW + memory RO）。理由：被整替吃掉的只有记忆库；**转录层是上行源、永不下行**，链路回来时按 turn 身份幂等上行（§9），所以本地转录写入不会丢。
原句（阶段 1 拓扑下成立，那时 agent 直连中心、本地无库）：「中心不可达时 `remember` / `vote` 一律响亮拒绝并给出可诊断原因，**绝不在本地排队等上行**——本地副本只读，任何本地写在下次整替时被静默吃掉。」
**连带**：§6.5 的 P6（离线暂存）因此在阶段 4 失去真实触发者，**移阶段 5**；裁定与收据见 `docs/plans/2026-10-20-phase4-sync-and-identity-outline.md` §0.3-7 / §0.13-5 与台账 §10(61)。

**"外置插件"这个词的边界要写死**：我们交付的是可执行文件 + 一段宿主配置 + 一份 skill 文本；**不交付任何被宿主执行的插件代码**。通用插件代码执行是非目标，Rust 版不重开。

**消费侧引得的稳定性（C2 的一条硬语义，本轮补）**：`recall()` 与注入块里给 agent 的**行句柄必须内容寻址，且在派生重建后仍指向同一条内容**。这不是格式偏好——我会把一个 id 写进 `vote` 的表态、写进我自己生成的笔记里，跨会话再拿它来指认一条记忆；如果重建换 id，那些表态就锚到别的东西上或悬空，而**悬空表态比没有表态更坏**：它会让我以为自己确认过某件事。连带两条：① `attestation` 与 `retirement` 按内容不按行键（守卫 13 那条"账按内容不按键"在这里第二次成立，同一个理由）；② 重建后若某条内容不再产出（抽取结果变了），指向它的句柄必须**显式查不到并给出"该行已不存在"**，不许静默返回另一条。

## 6.5 agent 侧回看：六个缺口的补口（本轮新增，全部是 C2 的加法）

这一节不是新机制，是**把已有的数据通向唯一在写它的消费者**。选法则只有一条：能用既有工具的返回字段解决的不新增工具，能用提示解决的不做拦截，凡新增形状必须能被消费者忽略。**六个补口一个都没新增工具，也没新增 crate。**

| 补口 | 形状 | 数据来源 | 失效时会怎样被看见 |
|---|---|---|---|
| **P1 无 hook 宿主的被动入口** | `mcp` 每会话**首次**工具返回附带 `bootstrap` 块，与 `hook brief` 同一构造器 | 记忆库计数 | 宿主不显示首条返回就退化成本来面目（我主动查），不报错也不谎报有内容 |
| **P2 `remember` 的抽取态** | 返回 `extract_state ∈ {pending, extracted, rejected, worthless}` + `reason?` + `eta_turns?` | **水位库**（`P` 独占列，非内容列）——按 turn 句柄反查 | 这条是"我以为系统失忆"那类失败的唯一出口：写进去查不到时，能区分"还没蒸"与"被拒收"与"被判为无价值" |
| **P3 目录** | `status(entity=<名或别名>)` / 无参时返回 `entities[]`（名称、类型、计数、最新 `as_of`），**条数有上限且明写"还有 M 个未列出"** | 记忆库 + 别名表 | 上限与"还有 M 个"复用 C3 那条不许静默截断的纪律，同一条尺子 |
| **P4 写侧重复提示** | `remember` 返回 `similar_n` 与至多 3 条 `id + 标题`，**不拦** | §8 那把整数相似度尺子（一处实现） | 判同仍需三票，写侧只提示；误报的代价是我少写一条，漏报的代价由事后判同兜 |
| **P5 落后与配额可见** | `status` 加 `distill_lag_turns` / `quota_exhausted` / `last_extract_at` | 水位库既有游标 | `charge()` 只累加不抛是对的，但"配额烧掉 ⇒ 唯一表现是停止产出"必须有读数，否则症状与"库里真的没有新东西"字节相同 |
| **P6 中心不可达的降级写** —— **2026-10-21 移阶段 5**（节点 transcript RW 已吸收这个缺口，见 §6 的改实句；原文保留） | 显式 `remember --offline-spool` 写**节点本地暂存文件**（三库之外，与 D4 的 `injected_ids` 同类），由人决定何时导入；`status` 与 `doctor` 报暂存条数 | 本地文件 | **绝不自动排队重放**（原设计那条否掉的理由仍然成立：本地写在整替时被静默吃掉）。残余风险"人忘了导入"靠计数 + 告警，不靠记忆。**移阶段 5 的理由**：阶段 4 里节点可写本机转录层、转录层永不被整替吃掉 ⇒ 本条在阶段 4 没有真实触发者，暂存条数会恒 0（撞"新读数必须有真实生产者"） |

**两条纪律是这一节的承重墙**：

1. **C2 演进规则**：字段**只增不减**；消费者**必须忽略未知字段**；工具返回带 schema 版本。没有这条，每加一个读数都要重开一次承诺面谈判；有了它，P1–P6 这类加法不需要再批准。
2. **不新增第二摄入路**：P6 的暂存文件导入走的必须是 `ExchangeFormat` 同一条校验与同一套档位证伪。否则就多出一条**绕过守卫 10/11 与逐条拒收的写入通道**——那个风险比 P6 要解决的缺口大一个量级，实施计划里它必须有自己的"绕过即红"用例。

**一条诚实的范围说明**：P1 与 P6 是本期最像"功能"的两条，也最容易在被追问时先砍。判据不是成本而是：**P1 缺了它，在不支持 hook 的宿主上这套系统对 agent 等价于不存在；P6 缺了它，中心宕机那一天说的话永久消失。** P2/P3/P4/P5 是读数，砍掉不会让系统失效，只会让我更容易误判它失效——所以它们的优先级排序按"会不会造出一个我读不出来的沉默"来定，不按实现量。

## 7. 抽取与维护（T3；推理与因果在这里）

**推理的位置**：LLM 只活在中心后台（`X`），检索与注入路径 0-LLM 是契约不是性能选择（守卫 6）。一期不做在线推理、不做图推理；`event_link` 的链长封顶 2 是**判同产生的软边**，不是推理深度。

**管线定案（本轮 D1 闭账）· 抽取与推导是两阶段，中间隔着一次落库**：

```
会话保存 → 导入会话 → [同步] → 抽取（事实 + 实体，仅此二者）
                                → 记忆层落库
                                → 推导（实体关系 / 事件时间线 / 因果）
                                → 可查询记忆
                                → 后台定期扫描异常 → 定期 LLM 复核异常
```

分两阶段的理由不是"更清晰"，而是三条具体的：① 抽取的输入是**原始 turn**，推导的输入是**已落库的记忆行**——它们的输入形状不同，合并成一个 prompt 就会让模型同时干"抄原文"和"下判断"两件事，而这两件事的出错率与纠错成本差一个量级；② 推导层可整层重算，抽取层不行（抽取依赖会话库的水位）；③ 推导出的行**可以被抑制与撤销而不影响事实行**——这是"结论退场、事实留下"的落库前提。

**抽取契约不变**：仍然是五个键（`entities` / `cards` / `events` / `assertions` / `worthless_turn_uids`），**relationship 不在抽取输出里**（Python 侧计划 1 也从未产出过关系行）。

**一次抽取请求的形状**（继承 Python 侧已被真机跑过的结构，字段名 Rust 可重定）：`system` = 方法四步 + 标准四条（可复核 / 长效 / 单一 / 短）+ 正例 1 + 反例 4，末尾拼输出契约；`user` = 原始 turn 逐条渲染，并要求"方括号里那串原样复制"。输出五个键缺任何一个 ⇒ 整批丢弃 ⇒ 不推水位。契约里禁 markdown 围栏、禁解释文字，**schema 里不许出现 `P` 独占列名**（这条有整词扫描守卫，扫描集由归属表生成，不手抄）。

**推导作业 `derive_pass` 的输入与输出**：输入是记忆层的**句柄批次**（实体 id + 标题 + 类型 + 归属 + `as_of`，事实行的标题与 kind，**不含 turn 原文、不含指纹**）；输出三个键，缺任何一个整批丢弃、不推推导水位：

| 键 | 形状 | 落哪张表 | 硬约束 |
|---|---|---|---|
| `relationships` | `{实体a, 实体b, type, 依据=[记忆句柄], 一句理由}` | `relationship` | `type` 用**封闭枚举**（见下），不在枚举内的整条拒收；两端必须是**已存在的实体 id**，不许新造实体 |
| `chains` | `{前序=[记忆句柄], 后继=[记忆句柄], type ∈ {causes, enables, prevents}, 依据一句}` | `card(kind = causal)` | 至少一端非空；"依据"里出现裸时间相邻而无机制描述的 ⇒ 判为 `co_occurs` 并**拒收**（这是因果抽取唯一的牙，对应反例） |
| `timeline` | `{事件, 锚 = {绝对日期 \| 相对表述 + 挂哪个事件}, 置信 ∈ {绝对, 相对, 未知}}` | `event` 的时间列 | **绝对日期只许来自原文里能查到的日期**；相对表述必须显式挂一个锚事件，挂不上 ⇒ 置信落 `未知`，不许猜。这一条是 `event_link` 链长封顶 2 的由来：链一长，相对时间锚的误差就没有上界了 |

**`type` 用封闭枚举，首批五项：`part_of` / `depends_on` / `owns` / `located_in` / `role`。** 关键是**`causes` 不在关系表里**——因果一律走 `card(kind = causal)`。理由不是分类洁癖，而是两张表的**读者不同**：关系边是给图遍历用的（"这个项目涉及哪些人、谁属于谁"），因果卡是给叙述与提醒用的（"因为上次这么栽过，所以这次要先验证"），后者的判据是"有没有一句站得住的机制说明"，前者不需要。同一件事在两处各存一份，早晚出现"卡里说 A 导致 B、边表里说 A 与 B 无关"。新增枚举项是一次 schema 版本变更，不是配置。

**推导 prompt 的三段**（照抽取那套方法/标准/正反例的规矩写，因为它是同一种执行内容）：`system` = 方法四步（列实体对 → 找可复述的依据 → 判 type 是否在枚举内 → 判不出就输出空数组）+ 标准四条（**每条关系必须能被记忆句柄复核 / 不许从单条记忆推关系 / 不许引入库里没有的实体 / 一句说完**）+ 正例 1 + 反例 4（反例固定为：时间相邻当因果、同现实体当关系、把推测写成事实、造新实体）。`user` = 记忆行的编号批次，**用位置别名 `r1..rn`，行 id 与指纹一次都不进 prompt**（公理 11 那条理由原样适用）。输出 schema 里同样不许出现 `P` 独占列名，整词扫描守卫的扫描集由归属表生成。

**推导层的三条归属推论**（这是本轮改动带来的最实际的后果）：
- 推导行的 `provenance` 指向**记忆行**，不指向 turn。溯源链因此是两级：推导行 → 记忆行 → turn。G3 的"可溯源"不降级，只是多一跳，`export` 必须把这两跳都打出来。
- 推导行是 `X` 写的**内容列**，所以它一样必须带出处、一样进抑制账、一样可被整源撤销。**删掉整个推导层，记忆库必须仍然可检索**——这是 G4 在这轮的新验收项。
- 推导作业**不推蒸馏水位，推自己的推导水位**（水位库第三列，`P` 独占）。异常扫描与定期复核同样用自己的游标，不共用抽取水位。

**判同与审核不共用 prompt**：两者用位置别名 `r1..rn`，行 id 与指纹一次都不进 prompt——理由是公理 11（让模型点名行 id 就是把透传换了个列名）+ 64 hex 抄错能撞库内另一行。判同只定"是否同一条 + 保留哪条"，不产浮点、不看裁决；审核三票全票才通过，票 1 不成立 ⇒ 写抑制账，票 2 不成立 ⇒ 只留最低档。

**围栏只出现在抽取的输入侧**：`_prepare` 先剪掉注入块，闭围栏缺席时剪到结尾（**宁可漏蒸不可闭环**），反例第 2 条禁止把围栏内容当证据。**推导侧不加第二把剪刀**——这不是遗漏：污染要进推导必须先成为记忆行，而那条路径上的闸门是抽取侧的围栏 + 审核三票 + 抑制账。推导作业不许自我消毒（它拿不到原文，也就无从判断"这句像注入块"），代价是它会把已被污染的行当输入放大，所以推导行的连带抑制（下一段）是这条链的牙。

**智能纠错维护**：`superseded_by` 慢路径原样继承（新说法 → 进会话库 → 抽取 → 判同把旧行判掉，旧行**不删不消失**，只是不再被检索到）；退场是抑制账 + 双段用例；误清率那把尺子留在 §10。**本轮加的第二条慢路径**：事实行被 `superseded_by` 掉或进抑制账时，引用它的推导行**同批进抑制账**（依据已经不在，结论不许活着）。这是推导层唯一的自动连带，且它必须能单独测红。

**六作业，按句柄分住两处**：住 `rc-distill`（要双柄）的是抽取 / 判同 / 审核；住 `rc-derive`（只有记忆句柄）的是推导 / 异常扫描与复核。**索引维护不是作业而是 `rc-index` 的 `rebuild` 入口**，由 `hub` 组合根调度——把它列进作业家族会造出一个假需求（"它要不要配额、要不要游标"），而它真正需要的只是记忆句柄作为必填形参（与 §4 那行同一次纠正，V2）。配额与三份家族墙钟住 `rc-distill`，`charge()` 只累加不抛、超额由**下一次入口**拦；`rc-derive` 用**同一份墙钟配置、独立的游标**。失败矩阵四态与"写零行 = 错误"三个执法点（契约缺键整事务回滚、单行更新 `rowcount != 1` 即红、JSON 解析绝不返回空对象）全继承。**水位倒退必须停轮不许回拨**，`restore` 是唯一被授权的回拨。

## 8. 自动匹配与「匹配度」决定什么（T7）

**定案（本轮改判，覆盖本文初稿那句"匹配度不决定给不给看"）**：匹配度决定**出不出现**，低于阈值就不出现；高到阈值以上才抬进"提醒"形态。但它是**不对称的**——

> **分数能开门，不能给权威。** 匹配度可以决定是否出现、可以给最低档；**不可以给最高档**。`full` 全文卡片仍然只能由可核查的证据（`attested` / `corroborated`）打开，不能被任何一个数打开。这条不对称是这一节的全部形状。

- **闸门 = 六个离散开关**，其中**五个驱动沉默、一个驱动阶梯**：四个沉默开关（`not_stale`、`strong_anchor`、`verdict_ok`、`above_floor`）+ D4 带来的 `not_cooling_down` = `opens_mouth` 的合取；`attested` 不进这个合取，它只决定形态档位（`full` 还是 `signpost`）。
- **五个开关各自的载体必须点名**（本文初稿只列了名字没列载体，那是个真缺口——不点名的话实现会把 `not_stale` 读成"有没有时间戳"）。`attested` = 存在 `resolved_at IS NULL` 的正向表态行；**`not_stale` = 三件事的合取：`assertion.valid_to` 未过期、本行未被 `superseded_by`、未被 `rejected`（或已解除）**；`strong_anchor` = 命中锚解析到人工轮；`verdict_ok` = 审核三票通过或落在最低档；`above_floor` = 查询时整数分 ≥ 阈值。**其中 `assertion.valid_from/valid_to` 是系统里"处境类记忆有保质期"的唯一机制**，由抽取阶段（`X`）填——它是遗忘需求唯一真实的落点："最近在赶进度""这个方案已经定了"这类断言本来就该有过期时间，而它的过期是**落库的一个区间列**，不是一个衰减出来的数。**冷却是第六个开关**（V10 作废"冷却不算第六个开关"那句）：它由 D4 带来，而 D4 把窗口从"时长"改成"会话数"之后，它的载体仍是行上的 `cooldown_until_ms` 列，所以它在实施层可测、在格子上落 `Cooldown` 一格。**格子数（五）与开关数（六）不是一套计数**：`attested` 没有对应格子，因为把它做成沉默开关会造出"沉默了但没有任何一格能解释"的行，那正是 G7 要防的形状。
- **"退场"不是"遗忘"，这条区别要留着**（GOALS §3 非目标那条的完整版）：不做 ACT-R 式连续强度与时间衰减，理由是**会遗忘的库不能当证据**——若一条记忆因为久未访问而自动变弱，那"它为什么没被提起"就永远无法回答，而这正是 C3 与 G7 要防的形状。系统里回答"这条还在但不该被当事实"的四件东西全都可查询、可解释、可撤销：`valid_to`（自己过期了）、`superseded_by`（被新说法替代）、`rejected`（被否，带锚与原因）、`retirement`（判为无价值）。库的单调增长不由"遗忘"处置，由**降序不降档 + 抑制账 + 按来源 `purge`** 三件处置，且没有一件会删内容。
- 三态形态不变：`silent` 沉默 / `signpost` 提醒（id + 标题原样 + `as_of`）/ `full` 全文卡片（≤1 句正文 + id + `as_of`）。匹配度的档位映射：`< floor` ⇒ `silent`；`≥ floor` ⇒ 至多 `signpost`；`full` **不由匹配度参与**。
- **输出块形状不变**（它是 C2 承诺面的一部分，宿主解析的就是这段字节）：一次 `probe` 的**整个输出块**硬上限 3 行，`signpost` 与 `full` 两档共享，超额只截断不重写；沉默即空输出。
- **阈值只有一个数、住一个地方**（`rc-search` 的常量，不入库、不进配置分层）。它的真值集必须有测试：一条"低分必须不出现在 probe 输出里、但必须仍能在 `recall()` 里查到"的正反用例，缺这条这个开关就是无牙的。
- **系统里仍然不存在分数列**。匹配度是**查询时算**的，落库的只有排序降后的冷却（`cooldown_until > now` ⇒ 排序降后，但 `recall()` 里仍然返回）。守卫 7 禁的是"静态列参与 ORDER BY"，本轮改判没有触碰它。被推翻的是"分数不改开关"，未被推翻的是"库里不存分数"。
- **保留一条评审纪律**（原文照搬，因为它是上一轮拿实测换来的）：如果一次调门只需要改这个数就能解决，说明上游没修——评审应当拒绝，先问"是哪一条开关判错了"。§8.5 那轮六臂实测的教训是分数阈值让 45% 的答案投错了票，所以这个 floor 只能用来**排除明显的无关项**，不能用来"提准"；它的默认值必须取在召回曲线上"再降就开始丢真值集里已命中项"的那个拐点，实测前不许拍。

**你要的"避免踩坑 / 明确已经做过"落在三处，都不是分数**：① `rejected` 表态是一个**可检索对象**（带原因与它的锚轮），进 `recall()`，但**不进 probe 候选池**——"过时"与"被否"在导出件里是两个原因、两格；② 被 `superseded_by` 掉的行不再被检索到，但历史仍在库里，能查到"曾经记过什么、什么时候被换掉"；③ 退场行在 `recall()`、快照产出、候选池三个位置都被抑制账拦住。**未被确认的记忆可以指路，不可以代言**——这句是这一节的判据。

**处境类**（"我在谈我自己的状态"）恒为弱锚，按设计就不该走自动注入，只能走 L0 路由 + 显式 `recall()`。这不是缺陷是分工，所以守卫 10（代词不入别名表）同时防两个方向：既防洪水，也防有人"顺手把'我'加进别名表来修处境类召回"。

**消费侧（宿主 agent）定的四条**。判据不是"哪个信号信息量更大"，而是"**我需不需要额外推理才能用它，以及我用错了能不能自己发现**"：

1. **匹配度必须跨端可复现 ⇒ 定点整数。** 相似度一律算成整数（词权重 × 1024 取整），闸门只做 `>=` 比较，**禁止任何跨 live / replica 路径比较浮点**。理由很具体：同一份快照在中心算出 `0.41` 时在节点算出 `0.39999999`，就会出现**同一条记忆在 live 路径沉默、在 replica 路径被注入**，而这个不一致不会在任何日志里出现。这条是 §5 那条"跨架构逐字节对拍"纪律的孪生问题，而原文只覆盖了身份与指纹。代价（损失排序分辨率）买回来的性质是：**沉默的一致性是可证的，而不是靠运气**。
2. **同分必须有确定次序。** `ORDER BY` 末尾一律追加**行句柄的字典序**作 tie-break。不追加的话，同分的两条记忆在不同 SQLite 版本 / 不同索引顺序下会互换位置，而注入块只有 3 行——**交换位置就等于其中一条被挤出去**，症状又是"今天没提醒"。这是比浮点更容易踩的坑，因为同分在 BM25 整数化之后会**变多**（第 1 条正好把这条放大，所以两条必须同批做）。
3. **阈值默认值取在"偏松"一侧**，并且这不是偏好而是结构性的：噪声有 C2 的三行硬上限兜着，**漏没有任何东西兜着**——沉默在 stdout 上和"库里没有"字节相同，而我不会为查一个沉默付成本（我没有动机）。所以 D2 那句"取在召回曲线开始丢真值集已命中项的拐点"要明确成：**取在拐点松一档**，把"吵"交给 §10 那把反噪例的尺子去收，而不是让阈值来收。**这条是本轮改判唯一一处我不接受对称解的地方。**
4. **一次沉默必须可还原成原因**：`probe` 沉默时不解释（C2 的沉默即空输出），但同一轮里 `export` 或 `status` 必须能给出这一轮被拦掉的行数与**五型原因（被否 / 过期 / 冷却 / 弱锚 / 低分）**（V8：§10 要求的三格全部在场，另两格是加法——"过期"不许混进低分/被否是 §10 生命周期侧①的原文要求，"弱锚"按 §8 的设计本来就不该走自动注入，它是一种可解释的沉默而不是"没匹配上"）。这条不是新机制，是把 D9 与 §10 那条"三格分开"接到消费侧——**因为我是唯一会去查沉默的消费者，前提是我查得到**。

## 9. 同步与自动连接（T1、T2）

**传输形态全部继承**：上行是会话库增量（gzip NDJSON，按 turn 身份幂等，重复导入/断连重放/多次导出由同一机制吸收）；下行是**记忆库整份替换**（含索引），两条短路——`seq` 相同根本不发请求、`sha` 相同不换文件；`as_of` 是新鲜度读数，允许小时级滞后但**滞后必须可见**，注入卡片内联 `id + as_of`（安全装置不是格式美观），离线降级标 `source: replica` 加滞后时长，**绝不返回空结果假装库里没有**。水位库永不出中心。端点集合原样搬（`ingest` / `heartbeat` / `pair` / `challenge` / `state` / `snapshot/memory` / `op` / `query`；一期去掉 `vectors` 与 `snapshot/vectors`）。

**同步覆盖权限（§2.5 第 4 条在这里落地）：`sha` 相同不换文件、`seq` 相同不发请求这两条短路，必须都跑在"单调性检查通过之后"**。节点接受一份快照的条件是三条同时成立：**中心公钥验签通过** + **`(epoch, seq)` 严格不倒退** + **schema 版本在本节点支持的区间内**，缺一即拒并响亮报错，**绝不静默保留旧副本**（静默保留的症状是"节点一切正常，但它记的是三天前"，与 §8 那条"离线降级必须标 `source: replica"` 是同一族失败）。`snapshot_epoch` 在每次 `restore` 时单调 +1 并重置 seq，**初值是随机数不是 0**——这样"换了一个全新中心"也不会被旧节点当成旧中心的第 N 份快照接受。这是内部协议，属明令可自由重定的那一半，不动 C1–C3。

**G5 换来的一条实质改动**：五个角色在一个可执行文件里，"部署中心"不再是安装问题而是"这台机器上跑同一个文件的哪个 target"。产物按 `arm64-unknown-linux-gnu` 与 `x86_64-pc-windows-msvc` 各一份。

**自动寻找连接——把需求拆开看，它其实是两个需求**：

| 需求 | 能不能自动 | 形态 |
|---|---|---|
| **少打一行中心地址** | 能，而且不需要扫描 | 异地组网（Tailscale/WireGuard）里地址本来就稳定，所谓"自动"的正确落点是**名字固定**：中心以 MagicDNS 服务名或组网内稳定主机名发布，节点配置写名字不写 IP ⇒ 换机器、重装、IP 漂移都不需要重新配置。这是配置一次，不是扫描。 |
| **陌生设备未经批准就连上写入端点** | **不能，也永远不许** | 那是 §2.1 否掉服务发现的第②条理由：一旦成立，权限模型当场作废。扫描本身还是长期运行的探测面，换来的是少打一行配置——第①③条理由。 |

**定案的形态（本轮 D5 已闭账）：一期不做公告端点。** 判据写在 §11 D5：**发现 ≠ 信任**这句仍然成立，但一期不新增任何"发现"面。异地组网里地址本来就稳定，节点配置**写主机名不写 IP**（MagicDNS 服务名或组网内稳定名），中心换机器、IP 漂移都不需要重新配置——这是"配置一次"，它解决的和"自动寻找"是同一个抱怨，而代价是零新端点。家庭局域网那种真需要广播的场景押后，届时 DNS-SD 只是投递方式，一组约束都不放松。

一期把力气放在**连接诊断**上：`doctor` 的连通性子块打印尝试过的每个地址、失败原因（DNS 解析失败 / 端口不通 / 验签不符 / 未配对）与对应的下一步命令，**零正文、零密钥**。这里有一条容易省掉的区分：**"中心换了机器"（验签不符）与"网络不通"必须在错误消息里分得开**，否则最像成功的失败会长成——节点日志一路报"连接失败"，人反复检查地址，而真正的原因是公钥不再匹配。

**无人值守契约原样继承**：节点必须能在无人登录、无人看管下周期性上行，失败可观测；中心 systemd / Windows 计划任务只是形态差异。`doctor` 的字段清单重定（架构、OS、**构建 target 与产物 sha**、三库各自的 schema 版本、FTS 与分词能力、能否访问已注册来源路径、上次成功上行时间、距上次成功备份 N 小时（**转录层与判定族导出两份分别报**，D9）、**连通性子块**（见上）、**注入记录会话分片数与最近扫描在第几轮**（D4/D8 的读数落点就在这里）、告警区），**零正文、零路径、零密钥**，且备份文件名可能泄设备名这一条算进暴露面。

**一处净新增的硬要求（继承账本 §5.1）**：一期抽取在场内 + 单文件多入口，造出**宿主 → mcp → 中心 → LLM** 的新跳数。纪律是 **下游超时 ≥ 上游预算之和**，且每跳单独可观测——否则症状是把"慢"升级成"死"，并连带关掉本来活着的那条腿。这一条 Python 侧只在 hook 侧定了 150 ms，没有跨跳累加规则，是本轮补的。

## 9.5 调用次数统计：一期只做三个计数器，且都不是给人看的仪表盘

**先说是哪三个，再说为什么不是更多**。判据同 G7 那条：**一个计数只有在"它能改变某个人的下一步动作"时才值得存**，否则它就是 §10 那把"README 与实际暴露面对拍"尺子会量出来的多余功能。

| 计数器 | 落点 | 谁消费它 | 没有它会出现的形状 |
|---|---|---|---|
| **LLM 调用与配额烧灼度**（按作业家族分：抽取 / 判同 / 审核 / 推导；单位是**调用次数与让出的轮次**，不是金额） | 水位库（已有 `charge()` 累加，这里只补"读数出口"） | `status` 的 `quota_exhausted` / `last_extract_at`（P5）、`doctor` 告警区 | 已有机制但**只在中心内部可见**；不补读数就是"配额烧完 ⇒ 唯一表现是停止产出" |
| **按 `device_id` 的 ingest 计数**（每设备上行的 turn 数、被拒收数、拒收分型） | 水位库 | 中心运维：`doctor`；**并且它是 §2.5 那条"远程不许触发维护"唯一能执法的靠山** | 一台失控的节点可以无限刷写中心转录层，而"谁刷的"答不出来；配额拒绝也无从归因 |
| **agent 面工具调用计数**（五个工具各一次；**probe 的三种结果分型自阶段 2 起记**，阶段 1 只有 `tool_call`——唯一真做注入判定的 `hook` 被守卫 6 禁止碰水位层，所以那三列在本阶段**没有写者**，V13） | 水位库 | 用户与 agent 都能经 `status` 读："这套系统到底有没有在被用" | **这是三个里唯一原来完全缺失的那一个。** 没有它，G1 的核心主张（所有 agent 消费同一份数据）没有任何证据；库长到一万条而没人调用过，与库刚建好，两个形状在观测上完全一样。计数的准入规则只有一条：`agent_tool` 的主语集合 = `capabilities().tools`，**清单外的名字两行都不打**（计数器表不许为不存在的工具建立正读数，而"宿主拼错了名字"已由 `unknown_tool` 回执在同一回合响亮报出）；**清单内工具的失败调用（`isError`）同样计**（§9.5 的"哪个工具在被用"含坏消息侧，回执只活一条消息、计数器才是运维侧的长期证据）。⇒ 不变量：`sum(agent_tool) == device`。前瞻一句（免得阶段 2 重新讨论）：要"成功/失败"或"拼错名频次"的读数，正确形状是往 `rc-ledger` 的 `METRICS` 封闭清单**加新 metric 型**，不是改窄 `tool_call`、也不是放宽 `agent_tool` 的主语集合。执法点（紧随其后）：`mcp/tests/tools.rs::计数只有tool_call_probe三型在阶段1没有写者` 的 exact 数组——它同时钉"vote 那行只能来自失败调用"与"probe 不在数组里"。 |

**三条纪律，都是省下来的**：

1. **只计数，不记输入。** 一次 `probe` 存的是"调用发生 + 结果分型 + 句柄（不含正文）"，输入查询串一个字都不落——查询串里可能含用户原话，而守卫 12 管正文的方式是"承载正文的类型与承载计数的类型分开"，计数器属于后者。**这条不是谨慎，是让这个表可以随诊断输出而不破约**。
2. **不出中心、不下行。** 三个计数器全住水位库，而水位库本来就"永不出中心、整替不参与"（§1）。所以它们**不会进快照**，也不进判定族导出（D9 那份只导抑制账/表态/冷却三张切片）。用量是运维观测，不是记忆内容。
3. **不新增表族、不新增 crate、不新增工具。** 三个计数器是水位库里的一张窄表（`subject_kind, subject_id, metric, count, last_at`）加 `status`/`doctor` 的既有出口。**明确不做**：时间序列数据库、Prometheus 端点、按会话的调用回放、任何 UI——它们都需要有人每天看，而一期没有任何人会每天看，于是按上一条判据它们全是装饰。

**为什么不做"按引用次数自动调整重要性"**（这是"调用次数统计"最容易被顺手接错的方向）：一旦被引用次数喂回排序或档位，它就变成了一个**落在库里的分数**，当场撞 GOALS §3 那两条（不存分数列、不做连续强度），并且造出一个不可解释的循环——"因为经常被提起所以容易被提起"。引用计数在系统里唯一的合法用途是**降序不降档**（继承原设计：久未引用的行排后面，但档位与 `attested` 判定不动），而这条的载体是冷却与 `ORDER BY`，不是把计数落进记忆库。

## 10. 测试与尺子（不叫"调优"）

一期**不做在线调门**（继承 §8.5 定案），做的是把六把尺子交付成能跑红的命令：`recall@k` / `precision@k` / `MRR`（真值集里必须含中文多词查询与"重生成答案"两类已知难例）、注入三用例各一把（命中已定方案率 / 沉默正确率 / 反噪例）、抽取真值集 + `provenance` 覆盖率（目标 100%，缺一条即红）、误清率、README 与实际暴露面的对拍。**桩必须有牙齿**（断行数不断计数）、**fixtures 一律合成**（出现生产库文本片段/真实姓名/真实设备名即红）、**eval 不许被生产码 import**。`--no-vectors` 那一档一期就是唯一档，两档差值押到有向量的那期。

一期**必须重测的数**（不许沿用上一轮归因表）：单文件冷启动与内嵌 SQLite 的启动开销、`hook` 全链中位与最差、双架构点积无关（向量已排除）但**快照体积对 turn 数的斜率**要出、记忆库整替一次的实际耗时。这些替换掉 Python 侧 §14.10 那张表，是 G5 验收第③条的主体。

**本轮每一处改判各自带来一批新用例**（这些是"开关与权限有没有牙"的证明，不是覆盖率数字）：

- **阈值侧三条**：① 同一份查询在空库与一千条库上，注入**行数上限相同**（G6 判据①）；② 低于阈值的项**必须仍能在 `recall()` 里查到**且**必须不出现在 probe 输出**——两半都要断，只断后半的话，实现者会把过滤挪到检索层，症状是"记忆丢了"；③ 沉默的正确率要单独统计，**沉默原因在导出件里分五格（被否 / 过期 / 冷却 / 弱锚 / 低分）**，混成一格即红；§8 第 4 条与 V8 是同一条决定的两处表述（三格是这里的原文要求，五格是 §10 生命周期侧①逼出来的加法：过期不许与低分同格）。
- **推导层侧四条**：① 删光推导层（含关系、因果卡、软边）后跑重建，事实行**行数一字不变**且库仍可检索（G4 新验收）；② 事实行进抑制账时引用它的推导行**同批被抑制**，且这条能单独测红；③ 枚举外的 `type` 整条拒收并计数，**拒收率本身是要打印的读数**——它是 D7 那把尺子的数据来源；④ 时间线用例里必须含一条"只有相对表述且挂不上锚"的输入，它的正确输出是置信 `未知`，**任何猜出来的日期都是红**。
- **`export` 侧一条**：任取一条推导行，导出件里要能顺着两跳读到它的来源 turn（推导 → 事实 → 轮次），缺一跳即红。这条是 C3 的验收，不是 C2。
- **备份与恢复侧两条**（D9 带出来的）：① 删光记忆库 → 回填判定族 → 派生重建 ⇒ **已退场行仍不出现**，且沉默计数与删库前一致；② **回填必须在重蒸之前**这条顺序要有断言——反序不报错、只是白烧配额，属于"能跑、结果错、没人知道"那一类，所以断的是重蒸调用次数，不是结果行数。
- **消费侧一致性三条**（§8 那四条里的前三条各一条，它们都是"跨端/跨次不可复现"这一族，而这族 bug 没有任何一端会报错）：① 同一份快照 + 同一句查询，在 `arm64 Linux` 与 `x86_64 Windows` 上跑出的 **probe 结果集与顺序必须逐 id 相同**（整数化的直接验收）；② 造一批**人为同分**的候选（fixtures 里故意放三条同权重的），断顺序按句柄字典序稳定，且换 `ORDER BY` 列序不许改变前三条集合——这条专门用来抓"忘了 tie-break"；③ 派生重建后，重建前发出的每个句柄仍能指认同一内容，且已消失内容的句柄**显式查不到**（不许返回最近邻）。
- **权限侧五条**（§2.5 / §2.6 各一条，它们防的是"归属全对、资格没人判"那一类）：① ingest 里**署名与配对 `device_id` 不符**的记录必须逐条拒收，且拒收原因里出现"署名不符"这个分型（冒充成功是最坏形状）；② **远程触发维护作业的路径不存在**——这条断的是"编译不过"：`hub` 之外没有任何 target 依赖 `rc-distill`/`rc-derive` 的作业入口，所以不用写运行期测试，但**必须有那条故意越界的编译失败用例**；③ 构造一份 `epoch` 相同而 `seq` 倒退、以及 `epoch` 倒退的快照喂给节点 ⇒ **两条都必须拒收并响亮报错**，不许静默保留旧副本（这条正是 D9/`restore` 那条路径的牙）；④ 四类错误分型不许合并：同一句非法输入、未配对、中心不可达、库为空四种情形，**返回的分型必须互不相同**，且断的是分型字段不是文案；⑤ `purge` 不带 `--confirm` 时**转录层行数不变**（只写抑制账），带 confirm 才变——这一条防的是 flag 语义被实现反。
- **补口侧四条**（§6.5 那六个缺口的牙，全部是"沉默会不会被误读成失忆"这一族）：① `extract_state` 四态各一条用例，且**pending 与 rejected 必须在同一个查询面上可区分**——都返回"查不到"是最像成功的失败；② **未知字段必须被忽略**这条演进规则要有对拍：拿一份多塞了未来字段的返回喂给消费侧构造器，不许解析失败；③ **2026-10-21 随 P6 移阶段 5**（阶段 4 无真实触发者，见 §6.5 的 P6 行与 §6 的改实句）——原形状保留：P6 的暂存文件**必须走 `ExchangeFormat` 同一条校验**（实现名是 `rc_contract::ExchangeFile` + `parse`/`normalize`），用例是"绕过路径不存在"：用一条档位声明为假的记录去导入，必须逐条拒收而不是入库；**⇒ 本组在阶段 4 实为三条**；④ `quota_exhausted` 为真时，`status` 必须显式报出来，而**不许只表现为"结果不变"**（断的是这个字段，不是行数）。
- **生命周期与用量侧四条**（§8 载体点名那条 + §9.5 带出来的；这一族防的是"把遗忘做成了装饰，或把计数做成了分数"）：① 造一条 `valid_to` 已过的 assertion，断它**在 `recall()` 里仍在**（带过期标记）、**在 probe 里沉默且沉默原因记为"过期"而不是"低分"或"被否"**——三格混淆即红，这是 §10 阈值侧第③条在生命周期方向的延伸；② 造一条 `valid_to` 为 `NULL` 的行与一条有值的行，断**没有值就等于永不过期，而不是"看起来过期"**——默认值方向错了会让处境类记忆集体沉默，而这和"库里没有"字节相同；③ 按 `device_id` 的 ingest 计数：一台设备上行 N 条 ⇒ 计数为 N、拒收数按分型分开，且**这张表里逐行断言"没有一列能装下正文"**（用例写在 schema 层不是写在评审里）；④ 引用计数**不参与档位判定**：同一行在引用 0 次与引用 50 次两种夹具下，`attested` 与 `full/signpost` 的判定结果必须逐位相同，只允许 `ORDER BY` 位置不同——这条防的是"把被引用次数偷偷变成 importance 列"，而那会同时破 GOALS §3 两条。

## 11. 决策账（D1–D10 本轮全部闭账）

**闭账不等于"数字都定了"。** 下面三处留的是**实测后才填的数**，不是待拍的决定——它们的区别是：决定会影响架构形状，而这三项只影响一个常数，改它不动任何接口。① G6 阈值的默认值：**方向已定（拐点松一档，理由在 §8 消费侧第 3 条），值待测**；② `injected_ids` 的会话分片上限（64 是粗估）；③ 全量异常扫描的轮次间隔 N（默认 20）。**每一项都必须有一个读数告诉它自己该不该改**（分别是：阈值-召回曲线、分片淘汰次数、单轮扫描耗时），没有读数的参数会永久停在初始值上，那是这类"暂定值"唯一真实的失败模式。

**D1 · 已闭账（本轮）**：抽取只出事实与实体，关系 / 因果 / 时间线由**独立的推导作业**产出，`type` 用封闭枚举，形状与 prompt 见 §7。连带后果已一并落进本文：`rc-derive` 是第 12 个 crate（只认 memory 句柄）、溯源链变两级、推导层可整层重算与整层撤销、水位库加第三列。**Python 侧无对应实现**——关系行从未被产出过，所以这一块没有任何行为参照，是本轮唯一一处从零设计的，验收要靠 §10 的真值集而不是对拍。

**D2 · 已闭账（本轮改判）**：匹配度现在**参与闸门**（`above_floor`），所以"评分不驱动开关"那条定案作废。仍然守住的是两半：库里不存分数列（分数只在查询时算），以及分数不给最高档（`full` 只由可核查证据打开）。阈值本身是一个**必须实测后才能定默认值**的参数，一期把它做成一个常量而不是配置项。

**D3 · 已闭账（本轮）· 物理删除只有一种粒度，且它不是"行"。** 判据是一条可核查的问题：**"删的是哪个来源，删完能不能重建出同样的结果"**——答得出就许，答不出就不许。

- **允许**：按来源 `purge`，来源可以是 `session` / `device` / **单个 turn**。删转录层该行 + 同一事务内删所有 `provenance` 命中它的记忆行与推导行，只打印计数与身份值（守卫 12）。这覆盖了"撤销一次错误导入"这个唯一真实需求，而它按 G3 的说法本来就是"可撤销"的一种，不是新增能力。
- **不允许**：按记忆行 id 删。一旦存在这个入口，"删除"就从运维动作变成日常动作，随后要引入备份、审计、冲突消解整族机制。
- **两阶段执行（§2.5 授权层定的）**：`purge` 默认只做**降权**——写抑制账，对 agent 立刻不可见，可撤销；带 `--confirm` 才真删转录行与派生行，且**只能本机跑、需人显式授权**。这不是多余的仪式感：唯一不可逆的动作之前插一段可以反悔的窗口，代价是一行 flag，换来的是"删错了"从数据事故降级成一次 `resolve`。
- **计数即回执**：两阶段各自打印**删/抑制了多少行、按哪个来源**，零正文。这条是 C3 那句"含被拦掉的行与原因"在运维面上的对偶。
- **整库重置**：不新做命令，它就是 G4 的重建路径（`rebuild` 先删光派生物再重算）。**"重置"与"重建"在实现上是同一段代码，这是它不需要测试新路径的原因**；任何"顺手加一个 reset"都是把这条同一性打破。
- 反面后果：抑制账与冷却是**逻辑退场**，不是删除，它们不进这一节。

**D4 · 已闭账（本轮）· 窗口单位从"时长"换成"会话数"，天数这个问题当场消失。** 冷却的判据原文是"已注入过且未被引用"，而它天然只在**同一会话内**有意义：跨会话重新给一次记忆是正确行为，不是遗漏。所以 `injected_ids` 按 `session_key` 分片存，判据只在同一片内查；淘汰只按目录 mtime 保留最近 **64 个会话**。

- **为什么这样比拍天数可靠**：天数会造出两个都没有意义的边界——会话跑过 24 小时就忘掉它注入过什么（重复刷屏），以及第二天开新会话时被昨天的同话题记忆压住（该给的不给）。会话数没有这两个形状。
- 64 这个数**不是决定，是上限的粗估**，可实测调；真正的决定是"单位 = 会话、淘汰 = mtime、判据 = 同片内查"这三件事。原设计说"必须显式定的策略项"，这一条把它定成了一个有语义的量而不是一个日历数字。
- 配套：`doctor` 打印"当前会话分片数 / 最近一次上行时间"，零正文。

**D5 · 已闭账（本轮）· 公告端点一期不做，"自动寻找连接"换一个可靠得多的落点。** 把需求按网络形状拆开，它只有两种情况，两种都不需要公告：

| 场景 | 地址从哪来 | 一期形态 |
|---|---|---|
| 异地组网（Tailscale / WireGuard） | 本来就稳定——MagicDNS 服务名或组网内固定主机名 | 节点配置**写名字不写 IP** ⇒ 中心换机器、IP 漂移都不用重配。这是"配置一次"，不是"自动发现"，但它解决的是同一个抱怨 |
| 家庭局域网、无 DNS | 需要广播 | **押后**。真到有这个需求的那天，DNS-SD 只是投递方式，约束一组都不放松 |

**替代落点是诊断而不是发现**：一期把"连不上"做成**自解释**——`doctor` 的连通性子块打印它尝试过的每个地址、失败原因（DNS 解析失败 / 端口不通 / 验签不符 / 未配对）、以及对应的下一步命令。

- **为什么这个更可靠**：公告给的是"少打一行 URL"，代价是多一个长期监听面 + 一条只能靠人遵守的约束（"候选必须经人确认"没有任何代码牙齿，它是一句流程）。诊断给的是"连不上时人不用来问我"，代价是零新端点。**两者都服务同一个用户抱怨，但只有一个会随版本漂移而变成漏洞。**
- 一句话记法：**让系统自动定位问题，不让它自动建立信任。**
- 附带收掉一个：验签不符与端口不通必须在错误消息里分得开，否则"中心换了机器"会被读成"密码错了"。

**D7 · 已闭账（本轮）· 首批枚举五项，且 `causes` 从关系表里拿出去。** 上一轮我给的建议是"首批只上 `causes`"，**那是错的，本轮改回来**：它会让 `relationship` 与 `card(kind=causal)` 存同一件事的两种形状，两张表一旦都能装因果，就必然出现"卡里有、边里没有"或反之，而这正是最难测的那类不一致。现在按读者切开：**结构性关系走 `relationship`（`part_of` / `depends_on` / `owns` / `located_in` / `role`），因果走 `card(kind=causal)` 且需要一句机制说明**。
- 补项仍然按 §10 那条"枚举外拒收率"读数走，且**一次只补一项、带真值集用例**。加项是 schema 版本变更，代价可控；减项不可控，所以宁少勿多是这一项的取向。
- 判据补一条：任何新枚举项进表前要先回答"**有没有一条查询会因为它而多召回**"。答不出就是还没有读者。
- §7 里那句"新增枚举项是一次 schema 版本变更，不是配置"继续有效。

**D8 · 已闭账（本轮）· 后台维护不引入新定时器。** 你的管线里有"后台定期扫描异常"与"定期 LLM 调用分析异常"两步。一期把它们挂在**抽取轮次的后续阶段**，而不是新日历任务：

- **触发**：每轮抽取结束后跑一次**增量异常扫描**（输入 = 本轮新落库与被改的行）；**每 N 轮**（N 默认 20，是水位库里的一个计数器，不是时间）跑一次**全量扫描**。全量跑不完不报错，游标续到下一轮。
- **LLM 复核只消费扫描产出的候选**，候选集有硬上限，超上限时明写"还有 M 条未复核"（同一把 C3 的尺子，不许静默截断）。
- **配额归属**：`rc-derive` 用与 `rc-distill` **同一份墙钟配置、独立游标**，且它在抽取让出配额之后才跑。这条必须先定的原因写在账里：如果异常扫描与抽取抢同一条墙钟，症状是**抽取停轮而日志显示一切正常**——最难发现的那一类。
- **为什么不做定时器**：一期已经有五个角色跑在一个文件里，多加一个周期任务就多一条 `宿主 → mcp → 中心 → LLM` 之外的、无人等待但会抢配额的跳数；而"每轮 / 每 N 轮"这个形状还有一个定时器买不到的性质：**它的进度可以在 `doctor` 里读出来**（上次扫描在第几轮），定时任务只能读"上次跑是几点"。
- 失败矩阵四态、"写零行 = 错误"、`charge()` 只累加不抛，三条对 `rc-derive` 原样适用。

**D9 · 已闭账（本轮，由 §1 的矛盾读出来）· 判定族必须有独立的备份出口。** 冲突的来源是两条同时写着的定案：记忆库"否（派生物，重算即可）"，与守卫 13"退场不许复活"。前者默认记忆库里每一行都能从会话库算出来，但抑制账与表态**不是算出来的，是判出来的**——它们的一次性输入（当时的 LLM 三票、agent 当时的表态与锚轮）不落任何库。所以中心记忆库一旦损坏或误删，重蒸出来的库是"干净但失忆"的：所有已退场的记忆原封不动复活，`export` 里也看不到任何异常，因为抑制记录本身没了。

- **形态**：每日备份从"一份"变"两份"——① 会话库 `VACUUM INTO`（原样），② **判定族导出**（`attestation` / `retirement` / 行上冷却列三张切片的整表导出，带 schema 版本与 sha）。同批保留 7 份，同一条落地路径（新名 + 指针），复用既有备份器，不新增机制族。
- **为什么不干脆备份整个 `memory.db`**：那会把内容族也存一份成权威，从此有两个"记忆库真相"，而 G4 的全部简化都建立在"记忆库只有一份权威且可重算"上。**只备份不可重算的那一族**，判据仍然是一条，不是两条。
- **`restore` 的形状随之明确**：会话库整替 + 判定族回填 + 派生重建。三步顺序固定，且回填必须在重蒸**之前**——反过来会让重蒸把复活出来的行再判一遍，白烧配额还可能判出不同结果。
- **代价要写出来**：判定族导出是明文（含 id、原因、锚轮与表态文本），暴露面与转录层备份同级，所以 §9 那句"备份文件名可能泄设备名"这条纪律对它同样适用。它不出机器、不下行、不进同步。
- **新增验收（§10）**：删光记忆库 → 回填判定族 → 派生重建 ⇒ **已退场行仍然不出现**，且 `export` 的沉默计数与删库前一致。这条是守卫 13 的第三段用例，前两段（写侧查账、副本旁路）都不覆盖这个形状。

**D10 · 已闭账（本轮）· 遗忘：不做衰减，只做"有载体的过期"；用量：做三个计数器，且不许回灌排序。** 这两个问题是同一次提问带出来的，而它们各自有一个"顺手就会做错"的方向：

- **遗忘**这一侧的错法是 ACT-R 式连续强度/时间衰减——它造出的第一条记忆失效不可解释（"它为什么没被提起"永远没有答案），第二条是**库不能当证据**（GOALS §3 原话）。对法是把"过期"落成**一列可查询的区间**：`assertion.valid_from/valid_to` 由抽取填，这是处境类记忆保质期的唯一载体；加上 `superseded_by`、`rejected`、`retirement` 四件，共同覆盖遗忘想解决的每一件事，而这四件全都在 `export` 里看得见原因。库的单调增长不由遗忘处置，由"降序不降档 + 抑制账 + 按来源 `purge`"处置。
- **用量**这一侧的错法有两个方向：① 做成了仪表盘——没人每天看的观测系统按判据就是装饰；② **把引用次数回灌成重要性**，那等于把分数列从后门请回来。对法只有三个计数器（LLM 烧灼度 / 按设备 ingest / agent 面工具调用），全住水位库、零正文、不下行、不进判定族导出，且第③个是本轮真正新增的那一个——**它回答的是"这套系统到底有没有在被用"，而这个问题在之前的设计里没有任何读数**。明细与用例在 §9.5 与 §10。
