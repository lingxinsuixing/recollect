recollect · agent-native memory · 2026

A traceable
agent memory substrate

The hub stores raw transcripts, runs extraction and publishes snapshots. A node on each machine follows along, and keeps organising locally when the network is down. Agents read what matters into context through one fixed entry point. Many devices and many agents share one copy, and by default it only runs on a trusted private network. Raw transcripts are the only source of truth; memory is just an index pointing at them.

What a recall looks like · view=brief Nothing is generated at read time

You discussed the deploy script on 10-22 and settled on one path: build-release.sh[1]; x86 and ARM artifacts each ship with SHA256SUMS[2]; cold-start readings live in that docs note, not in the memory body[3]。

For an LLM, reading one organised sentence costs less than parsing scattered fragments; the more scattered the fragments, the more likely the model fills the gaps itself.

Full sentences carry contextFragments and field dumps are not organised into context, so models fill the gaps. A complete sentence makes the who, the what, the time and the cause explicit, and is harder to misread.
No model call at read timeSentences are assembled by a template in code. Since nothing is generated on the read side, nothing can be invented at read time, and one round trip is saved.
Evidence on demandEvery [n] is a handle: follow it back to the original words. The full text never goes into the context.

01

Three claims decide everything else

This is not a feature list but a set of trade-offs. Each one below maps to a constraint in the code; read these three first and every pipeline that follows has a reason.

0 / 1

Code locates,
the LLM judges meaning

Ordinals, timestamps, speakers, tool calls, mentions, dedupe and provenance are all computed in code. Only the semantic judgements — entities, facts, relations, mood, ambiguity — go to the model, one question at a time.

0 / 2

Raw records are the source of truth;
memory is the index

A memory row holds a conclusion, a pointer to the source, and provenance. Full conversations, tool output, code and logs stay in the raw layer; when needed, follow the pointer back instead of copying the text into memory.

0 / 3

Identity is stable;
location is not

Identity is a computed hash: move it to another machine, import it again, and it is still the same record; seq a display number is not identity. Wherever the hub moves, the number still points at the same thing.

03

One hub, many edges, one authority

The hub itself needs no agent; each device runs a local node. A backup catches up entry by entry along the replication sequence and may only take over after verification; takeover rotates the credential, so anything the old hub still sends is rejected.

04

From one session to an expandable recall

Write and read are independent paths, separated only by a memory layer that can be rebuilt. Extraction failures, prompt revisions or a model swap never lose the original session.

01 / INGEST

Import

Each agent's own converter writes sessions into one format; if ingest checks fail, the converter is fixed. The core accepts no private format.

02 / EXTRACT

Extraction

Code locates first, then the LLM takes on semantic tasks. Every output carries only seq and a verbatim quote; no other fields are accepted.

03 / REVIEW

Review

Code checks everything that can be checked mechanically; then a separate model review flags problems without rewriting or re-extracting. Rejected drafts carry a reason.

04 / COMMIT

Land

The conclusion, handle and provenance enter the memory layer; the raw text stays in the transcript. Tests look at rows actually written — zero rows is an error.

05 / RECALL

Recall

By default you get a brief with handles — the marker at the start of each line — [1]; use it to fetch that memory. The turn pointer in the memory then takes recollect_turn you back to the raw words. Programs read json; reviewers use expand to see the evidence chain.

06

Why it is built this way

Each one answers a real trap we hit; nothing is complex for its own sake.

Close the conversation and the context is gone
→
The raw text stays; a pointer finds it any time
Models invent, especially times and numbers
→
Code locates; the model only judges meaning
When a conclusion does not match its source, you cannot see where it went wrong
→
Every row carries the source position and time; it can be retracted or superseded
Swap the model and everything has to be redone
→
Memory holds conclusions only; the raw text is untouched, so a re-run is enough
On a small machine, embedding models are too heavy
→
Start with exact keyword recall; add vectors as an optional table later, never in the core
One person cannot maintain a fleet of services
→
One binary, SQLite only, no message queue
One executableNo external services, no console window; copy it over and run.
One machine is the hubWithout a hub, this machine is the hub; with one, it is just another role.
SQLite onlyNo message queue, cache or search cluster; when something breaks you can open the file and look.
Keeps working offlineOne day offline, keep organising locally; five days, act as your own hub; when the network returns, merge back in a fixed order.

Memory should be groundwork,
not a by-product of a plugin.
