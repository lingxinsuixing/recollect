08 / SOLO · 一台设备，一个 agent

就一台电脑，
一个 agent

没有第二台机器，也没有同事 agent。这套记忆还成立吗？ 成立——本机就是中心，大部分多机功能会自己退到后台。 下面用 DSH 里最火的大肥鱼举例。

01

能跑，但只跑其中一半

单机不是残废版：日常该有的记忆能力都在；用不上的，是那些本来就为“第二台设备”准备的东西。

01 / 会跑

本机就是中心

不需要第二台机器。导入、抽取、召回、备份都在这一台上完成；一个数据目录就是全部。

02 / 会记

一个 agent 的长期记忆

core 只属于它；世界记忆也只有你们两个人。新会话不用从头讲，昨天的事还在。

03 / 不会启动

多机那套留在抽屉里

配对、复制、快照、跨机转录读不会自己跑。不是坏了，是没有第二个对象可以连。

02

大肥鱼：一个陪伴角色，一台设备

先分清一件事：DSH（DeepSeek Harness）是 agent 运行环境，大肥鱼是社区里最火的陪伴角色——桌宠是外形，人格设定是说话方式。真正读文件、跑任务的是 DSH 里的 agent；桌宠把它的状态画出来。

CASE · DSH / 大肥鱼

它记得人设，
但记不住前天那句

你只有一个主人、一台电脑。它的人设很稳定，说话方式也一直像那条鱼； 但新会话一开，前天那句「猫周三复查」还是容易掉。

把 DSH 的会话按契约导进来，recollect 在本机留一份记忆。 DSH 这一路用的是仓库里的 tools/converters/dsh_v1.py：它把会话转成统一事件，验收不过就改转换器，不改核心。 下次开新会话，agent 先读到的是结论 + 句柄，而不是整段聊天； 要核对，再按句柄翻回原话。

它仍然只有一个 agent。没有第二个 agent 来跟它共享记忆，也没有第二台机器来同步。 这不是缺陷，是单机场景本来就不需要那套。

召回 · 一句话

你上周说猫周三复查，昨天改到周五；出门前记得带航空箱[1]。

03

一台设备和两台设备，
差在哪

同一套东西，只是启用的范围不同。切换看看哪些会跑，哪些会被留在抽屉里。

扩展是加法，不是前提

单机先把记忆跑起来；第二台设备来了，再加配对、复制和跨机读取，不用重装一套。

1台设备 / 1 个 agent
  • 本机 hub、抽取与召回会跑
  • 会话导入（agent 侧转换器）会跑
  • 关键词搜索与原文回放不需要模型
  • 配对、复制、快照、跨机转录读不会启用
  • 本机备份建议开着
2台设备 / 多个 agent
  • 中心 + 每台设备的节点会跑
  • 一次性配对启用一次
  • 复制、快照与断线回落会启用
  • 跨机转录读已配对设备可读
  • 本机备份仍然要开
04

一天里，记忆做了什么

单机也一样：不是把聊天记下来，是在几个关键时刻把该记的递回来。

  1. 09:10 · 新会话
    不用从头讲

    它先看到昨晚那句「猫周三复查，改到周五」；先问航空箱，而不是重新问你养了什么。

  2. 12:30 · 你让它记一笔
    小本本只增不改

    「周五前提醒我」写进 core 的小本本；摘要自动进下一次开场，不用你再说一遍。

  3. 20:00 · 你问部署脚本
    先给一句话，再给证据

    它答「统一走 build-release.sh」并带 [1]；沿着 [1] 能翻回那天的原话，不靠它复述。

  4. 23:00 · 你说不想聊工作
    情绪有有效期

    这条是当时的状态，不是永久标签；第二天它不会一上来就催进度。

案例仅作示范；单机场景下，这些动作都在本机完成。

05

最小起步：四步，不用配对

先跑起来，再决定要不要第二台设备。单机路径没有服务端、没有节点、没有一次性码。

01 / 下载

校验、解压

拿到对应平台的 release，先核对 SHA256；安装器不改宿主配置，也不带数据。

02 / 建目录

一个数据目录

找一个本地目录作为 --data-dir；首次启动是空库，所有东西都在这里。

03 / 导入

会话按契约进来

DSH 的会话格式由 agent 侧转换器负责；转换器不过验收就改转换器，不改核心。

04 / 接上

MCP 加一个身份

给这个 agent 一个 id，core 的钥匙就只对它开放；不需要 hub serve。

solo · 本机起步示意命令
$ recollect-hub import --data-dir ./data \ ./dsh-session.json $ recollect-mcp --data-dir ./data \ --agent-id dafeiyu # 文件名是示例；DSH 的会话先过 agent 侧转换器，按入库契约进来
06

单机不等于高安全

单机少一层网络暴露，但不少一处该守的边界：盘、钥匙、端口、模型出口，四件事都得自己守。

一块盘 备份要加密，也要分开放

hub backup 解决坏盘，不解决“整台机器被拿走”；备份和密钥不要只留在这块盘上。

一把钥匙 core 钥匙丢了、漏了都麻烦

每个 agent 的小本用独立钥匙；钥匙丢了正文解不开，漏了等于公开。钥匙不进备份、不进模型，单独归档。

一个端口 不要把中心开到公网

单机也会被扫到。默认只在本机或可信局域网监听；异地用隧道或组网，别把 serve 端口直接暴露出去。

一段原文 抽取会把原文送进模型

要出网的只有当前这一轮；密钥只在本机，秘密和身份字段先扫一遍再送。没有模型时，搜索与回放照常。

设备少，不等于边界少；安全是配置出来的，不是单机自带的。

设备可以只有一台，边界不能只有一层。
